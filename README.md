# 虚拟演出观众席布置工具

面向虚拟演出制作的**万级观众席布置与应援色编排**工具。企划给场馆座位图、灯光指导给区域色温、商务给赞助方应援色与露出区块，工具把座位点阵、观众形象、荧光棒配色、站坐姿态、曲目段落联动到同一个俯视图工作台，并输出可被灯光/机位团队在预演中调用的锁定方案。

技术栈：**React 18 + TypeScript + PixiJS v8 + pixi-viewport v7 + Vite**。

## 启动

```bash
npm install
npm run dev        # 开发，默认 http://127.0.0.1:5173/
npm run build      # 类型检查 + 生产构建
npm run preview    # 预览生产包
```

## 工作流（与业务角色对应）

| 步骤 | 角色 | 操作 |
| --- | --- | --- |
| ① 导入座位图 | 企划 | 一键生成 60 排、中央+左右翼三分区、带过道缺口的弧形场馆，共 **23,256 个座位**，按排建立索引 |
| ② 形象库填充 | 视觉/企划 | 把 5 类观众形象（应援团/普通/VIP/亲子/媒体）拖到看台，按色温区域批量填充，每人独立生成服装色、荧光棒色、站/坐姿态 |
| ③ 框选涂色 | 商务 | 框选第 12–18 排（赞助露出区块），荧光棒一键统一为赞助方橙色，选中人数实时跳到实际值 |
| ④ 遮挡遮罩 | 舞美 | 对被道具挡住的排做区域遮罩，渲染量同步下降，可按原位置恢复 |
| ⑤ 摆位核查 | 企划 | 自动检测落到过道、舞台边的座位 |
| ⑥ 曲目段落 | 导播 | 拖动段落滑块，前/中/后区按副歌/主歌不同比例站起，逐排延迟形成人浪 |
| ⑦ 锁定交付 | 制作 | 锁定整套布置与区域配色，导出 JSON 供灯光与机位预演调用 |

## 核心交互

- **滚轮缩放 + 拖拽平移 + 惯性**：pixi-viewport，缩放范围 0.08–4 倍
- **近处看姿态，远处看色块**：三级 LOD——远景只画服装色点连成应援色块；中景加荧光棒；近景显示站/坐人形与辉光
- **点选观众**：侧栏显示座位号、分区、形象、服装色、荧光棒色、姿态；右上角 2D 透视预览同步高亮并画引线
- **透视预览**：独立 canvas 伪透视投影，模拟机位视角，遮罩排跳过绘制
- **统计条**：座位总数、已布置、当前选中、站立、遮罩、实际渲染精灵数、FPS，250ms 节流刷新

## 性能设计（几万人同屏跟手）

- 全部逐人数据放在 **typed array**（`Uint8Array` 标志位 / `Uint32Array` 配色 / `Float32Array` 姿态），不进 React state，零对象分配
- 姿态变化在 tick 内逐人缓动，React 只接收节流后的汇总数字
- **视锥裁剪**：屏幕外精灵直接 `visible=false`，渲染量随取景范围变化（底部“实际渲染”可见）
- 贴图运行时矢量生成、`tint` 上色，全站仅 5 张小贴图，避免上万纹理切换
- 框选/遮罩走按排索引 `rows[][]`，不做全量扫描之外的重复计算

## 目录结构

```
src/
  data/
    venue.ts        # 场馆座位点阵生成（弧形排、三分区、过道、赞助区块）
    presets.ts      # 色温区域、赞助方、形象库、曲目段落预设
  pixi/
    AudienceEngine.ts   # 主引擎：渲染、LOD、交互、框选、遮罩、段落、导出
    audienceState.ts    # typed-array 观众数据层 + 批量填充
    textures.ts         # 运行时贴图生成
  components/
    LeftPanel.tsx       # 导入、形象库拖放、色温、赞助信息
    RightPanel.tsx      # 框选、遮罩、摆位核查、人物详情、锁定导出
    BottomBar.tsx       # 统计条 + 曲目段落滑块
    PerspectivePreview.tsx  # 右上角透视预览
  App.tsx, main.tsx, types.ts, styles.css
scripts/
  smoke.mjs             # Playwright 端到端冒烟测试
```

## 自动化测试

```bash
npm i -D playwright && npx playwright install chromium
# 先启动 dev server，再：
APP_URL=http://127.0.0.1:5174/ node scripts/smoke.mjs
```

冒烟测试覆盖：导入填充、框选 12–18 排、橙色涂色、缩放平移、点选详情、遮罩/恢复、副歌人浪、摆位核查、方案导出，共 12 个环节并断言零页面错误。

> 注：headless 软件渲染（SwiftShader）下 FPS 仅 15–25，属预期；独立 GPU 上同规模场景可达流畅帧率，实际渲染精灵数随取景动态变化。

## 导出方案格式

`stage-audience-plan-*.json`：场馆与区域色温、形象库映射、遮罩排、锁定标志，以及每位观众的 `[座位id, 形象idx, 服装色, 荧光棒色, 姿态]`，供预演环境直接重建现场。
